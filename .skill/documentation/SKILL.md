# Documentation Best Practices (Repository Level)

All projects and distributed artifacts within the BACH repository must follow comprehensive documentation standards.

## When This Skill Applies

This skill should be automatically invoked when:
- Creating or editing markdown (.md) files
- Discussing documentation standards and best practices

## Guidelines for README.md

When creating or updating a README.md file, ensure it includes the following sections:

- **Introduction**: A brief overview of the project/library and its purpose
- **Features and Capabilities**: A detailed list of what the project can do
- **Installation**: Step-by-step instructions for setup and installation
- **Usage**: Comprehensive usage instructions with examples
- **Dependencies**: A list of all required external commands, environment variables, or files
- **Contributing**: Guidelines for contributors (where applicable)
- **License**: License information and copyright notices

## Examples-Based Documentation

The features description and usage instructions MUST be examples-based, showing how to use the library or tool in different scenarios.

For each feature or capability:
1. **Introduce** the feature and explain its purpose
2. **Provide a clear example** with:
   - Executed command lines
   - Expected output
   - Explanation of what happened
3. **Explain behavior** in various scenarios:
   - Success cases
   - Edge cases
   - Error handling



## Documentation Quality Checklist

- [ ] Clear and concise language (avoid jargon where possible)
- [ ] Accurate and up-to-date information
- [ ] All examples are tested and working
- [ ] Consistent formatting and structure
- [ ] Links to related documentation
- [ ] Complete list of dependencies
