# Contributing - Usage

How to work on the Bach repository locally: run the tests, preview the documentation and refresh the examples outputs. All the commands are run from the repository root with `make`.

## Requirements

| Tool | Used for |
|---|---|
| bash 4.0+ | Libraries, tests and demos (associative arrays and namerefs) |
| `tput`, `curl`, `git`, `sha256sum`, `awk`, `sort` | Libraries (see the dependencies of each library) |
| Node.js 22+ and npm | Documentation site ([VitePress](https://vitepress.dev)) |
| Python 3 | Refresh of the examples outputs of the documentation |

## Make commands

`make help` lists the available targets.

| Command | Description |
|---|---|
| `make test` | Run all the test files of the repository (`**/*.test.sh`) |
| `make test-libs` | Run the test files of the `libs/` folder |
| `make docs-preview` | Install the documentation dependencies and serve the documentation locally with live reload |
| `make docs-build` | Build the documentation site (output in `docs/.vitepress/dist/`) |
| `make doc:fix` | Re-run the usage examples of `libs/*.md` and refresh their "Expected output" blocks |

## Run the tests

Tests are executed by the test runner `tests.sh`, which finds the `*.test.sh` files matching a pattern, runs them and prints a summary.

```shell
# Everything
$ make test

# Only the libraries
$ make test-libs

# A pattern, with the runner
$ ./tests.sh "libs/parse_args.test.sh"

# A single test file, directly
$ bash libs/parse_args.test.sh
```

A test file exits with a non-zero status when a test fails, so the commands can be used in scripts and CI.

## Documentation

The documentation of the libraries is the `libs/<lib>.md` files; the site is built from them, from the `README.md` and from the files of `docs/`.

```shell
# Preview at http://localhost:5173 (live reload)
$ make docs-preview

# Production build
$ make docs-build
```

The site is published on GitHub Pages by the `Docs` workflow (`.github/workflows/docs.yml`) on each push on `main`.

### Refresh the expected outputs

The usage examples of the libraries documentation are runnable: each `::: code-group` of the "Usage Examples" section is followed by an "Expected output" block, generated by running the "With bach" snippet.

```shell
# Refresh all the libraries documentation
$ make doc:fix

# Refresh one library, or preview the changes
$ python3 docs/scripts/update_outputs.py parse_args
$ python3 docs/scripts/update_outputs.py --dry-run
```

The snippet is executed in a sandbox where `lib/bach/` links to the repository. An HTML comment right before the code group gives the arguments and the environment of the run:

```markdown
<!-- args: --verbose --output=json report.txt -->
<!-- env: LOG_LEVEL=info -->
::: code-group
...
:::
```

Run `make doc:fix` after any change of a library or of its examples, and commit the updated documentation. Non deterministic values (timestamps, temporary paths) are replaced by fixed ones.

## Demos

The `demo/<lib>/demo.sh` scripts demonstrate each library. Run them from their folder:

```shell
$ cd demo/log && ./demo.sh
```

## Workflow

1. Create a branch from `main`.
2. Change the library, and its tests and documentation (see the [conventions](conventions)).
3. Run `make test` and `make doc:fix`.
4. Commit using the [commit message convention](conventions#commit-messages) and open a pull request.
